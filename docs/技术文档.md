## 一、系统概述

### 1.1 项目定位

本系统是一个**AI驱动的对话式数据分析工具**，用户通过自然语言提问，系统自动完成：

1. 理解用户问题意图
2. 将自然语言转换为SQL查询
3. 执行查询并获取数据
4. 对结果进行统计分析和可视化
5. 支持异常检测、时序预测、报告生成等高级功能

### 1.2 核心指标

| 指标 | 目标 | 实际 |
|------|------|------|
| NL2SQL准确率 | ≥80% | 见评测报告 |
| 查询响应时间 | <5s | 取决于LLM延迟 |
| 支持数据源类型 | 5种 | SQLite/Excel/CSV/MySQL/PostgreSQL |
| 图表类型 | 4种 | 柱状图/折线图/饼图/散点图 |
| 高级分析 | 3项 | 异常检测/时序预测/报告生成 |

### 2.2 核心技术链路

```
用户提问 → 意图分类 → Schema映射 → NL2SQL生成 → SQL校验
                                                    ↓
用户 ← 可视化+报告 ← 统计分析 ← 异常/预测/报告 ← 查询执行
```

### 2.3 数据模型

所有模块间通信使用Pydantic模型，定义在 `backend/shared/schemas.py`：

- `ChatRequest` / `ChatResponse` — 对话请求/响应
- `QueryResult` — 查询结果（columns + data + row_count）
- `TableSchema` / `ColumnInfo` — 表结构元信息
- `ChartConfig` — 图表配置
- `AnalysisReport` / `AnomalyResult` / `ForecastResult` — Phase 3分析结果

## 三、模块详解

### 3.1 NLP层

#### 意图分类 (`intent_classifier.py`)
- 将用户问题分类为：`SQL_QUERY`, `ANOMALY_DETECT`, `FORECAST`, `REPORT`, `CHAT`
- 使用LLM + 规则混合策略

#### Schema映射 (`schema_mapper.py`)
- 将用户问题中的自然语言术语映射到数据库字段
- 支持中文字段名匹配
- 提供JOIN关系推荐

#### NL2SQL生成 (`nl2sql_generator.py`)
- LangChain pipeline: ChatPromptTemplate → ChatOpenAI → StrOutputParser
- 根据意图类型选择不同的System Prompt
- 支持单表查询、多表JOIN、聚合统计

#### SQL校验 (`sql_validator.py`)
- 表名/列名白名单校验
- 危险操作拦截（DROP/DELETE/INSERT/UPDATE）
- SQL长度限制

#### 对话管理 (`conversation_manager.py`)
- 内存字典存储多会话
- 每会话最多保留20轮对话
- 超长自动压缩（保留头尾+中间摘要）
- 提供REST API查询/删除

### 3.2 分析引擎

#### 统计计算 (`stats_calculator.py`)
- 基础统计：count/mean/std/min/25%/50%/75%/max
- 偏度、峰度、缺失率

#### 异常检测 (`anomaly_detector.py`)
- **IQR法**（≥10行）：四分位距，Q1-1.5×IQR ~ Q3+1.5×IQR
- **Z-Score法**（≥30行）：|z| > 3 阈值
- **Isolation Forest**（≥50行）：sklearn集成方法
- 自动根据数据量选择方法
- 输出ECharts散点图标注异常点

#### 时序预测 (`forecaster.py`)
- **Prophet**（主要）：自动检测趋势+季节性+变点
- **移动平均+线性外推**（回退）：无依赖，使用numpy polyfit
- 自动识别日期列和数值列
- 输出预测点+置信区间+趋势方向

#### 报告生成 (`report_generator.py`)
- 组合StatsCalculator + ChartRecommender + LLM
- LLM生成：标题、摘要、洞察、建议（JSON格式）
- 无LLM回退：自动从统计结果生成洞察
- 输出MetricCard KPI卡片

#### JOIN分析 (`join_analyzer.py`)
- 三策略自动发现：FK约束(confidence=1.0) → 字段名匹配(0.65-0.85) → ID命名规律(0.75)
- 返回去重唯一表对推荐
- 提供`format_for_prompt()`格式化输出

#### 公式引擎 (`formula_engine.py`)
- 安全eval：白名单+禁止token过滤
- 支持：`new_col = expression`, `IF(cond, true, false)`, 聚合函数
- 自动推荐可用公式

### 3.3 数据源适配层

| 适配器 | 引擎 | 适用场景 |
|--------|------|----------|
| SQLiteAdapter | sqlite3 | 本地数据库文件 |
| DuckDBExcelAdapter | DuckDB | Excel(.xlsx/.xls), CSV |
| SQLAlchemyMySQLAdapter | SQLAlchemy + PyMySQL | MySQL 5.7+/8.0 |
| SQLAlchemyPostgreSQLAdapter | SQLAlchemy + psycopg2 | PostgreSQL 12+ |

统一接口：
```python
class BaseAdapter(ABC):
    def connect(self) -> bool
    def get_schemas(self) -> List[TableSchema]
    def execute(self, sql: str) -> QueryResult
    def close(self)
```

### 3.4 可视化引擎

#### 图表推荐 (`chart_recommender.py`)
- 规则：列数→图表类型
  - 1数值+1分类 → 柱状图
  - 1日期+1数值 → 折线图
  - 2分类+1数值 → 堆叠柱状图
  - 1分类+1数值(≤10类) → 饼图

#### ECharts构建 (`echarts_builder.py`)
- 生成完整ECharts option JSON
- 支持tooltip/legend/dataZoom/响应式

## 五、部署说明

### 5.1 环境要求

- Python 3.10+
- 8GB+ RAM（推荐16GB）
- （可选）Docker & Docker Compose

### 5.2 方式一：启动脚本

**Windows：** 双击 `start.bat`
**Linux/Mac：** `chmod +x start.sh && ./start.sh`

脚本自动完成：依赖检查 → 启动后端(8000) → 启动前端(8501)

### 5.3 方式二：Docker Compose

```bash
# 核心服务
docker-compose up -d

# 含数据库
docker-compose --profile with-db up -d
```

服务端口：
- 后端API: `http://localhost:8000`
- 前端界面: `http://localhost:8501`
- API文档: `http://localhost:8000/api/docs`
- （可选）MySQL: `localhost:3306`
- （可选）PostgreSQL: `localhost:5432`

### 5.4 配置说明

默认使用九天平台大模型（AppCode Bearer 鉴权），密钥通过系统环境变量设置，**不存储在项目文件中**：

```bash
# Windows CMD
setx JIUTIAN_APP_CODE "你的AppCode"

# Windows PowerShell
[Environment]::SetEnvironmentVariable('JIUTIAN_APP_CODE', '你的AppCode', 'User')

# Linux/Mac
export JIUTIAN_APP_CODE="你的AppCode"
```

服务地址与模型名在 `config/settings.yaml` 中配置（默认已指向九天 `generate_stream`）。切换其他 Provider 时另设对应环境变量：
- `DEEPSEEK_API_KEY` — 切换 DeepSeek 时使用
- `OPENAI_API_KEY` / `QWEN_API_KEY` — 其他 Provider

## 七、安全设计

### 7.1 API Key管理
- 密钥仅存储在系统环境变量/Windows注册表中
- 代码中不包含任何硬编码密钥
- 所有配置文件使用占位符

### 7.2 SQL注入防护
- SQL校验器白名单过滤：仅允许SELECT查询
- 表名/列名必须在Schema中注册
- 禁止DROP/DELETE/INSERT/UPDATE/ALTER等操作

### 7.3 公式引擎安全
- 禁止token黑名单：`__`, `import`, `exec`, `eval`, `open`, `os`, `sys`等
- 白名单函数：仅允许abs/round/sum等安全运算
- 回退到逐行安全eval（`__builtins__={}`）
